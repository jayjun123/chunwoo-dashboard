> 발표·공유용 요약 문서입니다.

## 1. 한 줄 요약

Firebase 기반의 **건설 현장 통합 운영 웹앱(PWA)** 입니다.  
현장·일정·기성·견적·재고·안전·정산 등을 한 화면 체계에서 다루며, 멀티 디바이스(웹 / PWA / Capacitor)를 목표로 합니다.

| 항목 | 내용 |
|------|------|
| 프론트엔드 | React 18, Vite, MUI 7, React Router |
| UI | Layout 셸(AppBar·Drawer·BottomBar), PC/모바일 분기 |
| 백엔드 | Firebase Auth / Firestore / Storage |
| 보조 서버 | Netlify Functions, NAS API(메일·AI 등) |
| 배포 형태 | PWA + Capacitor(Android/iOS) + Electron(선택) |

## 4. 인터페이스 · UI 구성

기능(라우트)만으로는 부족했던 **화면 껍데기 · 조작 방식 · PC/모바일 차이**입니다.  
UI 기반: **Material UI (MUI) 7** + 커스텀 다크 톤 셸.

### 4.1 앱 셸 (공통 레이아웃)

```
┌──────────────────────────────────────────────────────────┐
│ [PC] 상단 AppBar                                          │
│  로고 │ 아이콘 메뉴(가로) │ 알림 · 테마 · 계정               │
├──────────────────────────────────────────────────────────┤
│                    본문 (페이지)                            │
├──────────────────────────────────────────────────────────┤
│ [공통] 하단 BottomBar (날씨·할일·바로가기·뱃지 등)            │
└──────────────────────────────────────────────────────────┘

[모바일] AppBar 숨김 → Drawer(햄버거) + 본문 + BottomBar
```

| UI 요소 | 역할 |
|---------|------|
| **AppBar (PC)** | 로고, 가로 아이콘 메뉴, 알림, 다크/라이트, 프로필 |
| **Drawer (모바일)** | 동일 메뉴를 사이드로 표시 |
| **BottomBar** | 하단 고정 — 날씨, To-Do, 토론/알림 뱃지, 관리 바로가기 |
| **ThemeContext** | 라이트/다크 토글 |
| **ProtectedRoute / PermissionGuard** | 로그인·메뉴 권한 제어 |
| **SplashScreen** | 초기 로딩 |
| **SwipeableContainer** | 모바일 스와이프 |
| **IdeaPad / Notepad / Paint** | 메모·그림 오버레이 |

### 4.2 PC vs 모바일 분기

| 패턴 | PC | 모바일 |
|------|----|--------|
| 내비 | 상단 아이콘 메뉴 | Drawer + 하단 바 |
| 일정 | 좌측 현장 리스트 + 캘린더 DnD | 터치·롱프레스, 날짜간 DnD 제한 |
| 토론 | 카카오톡형 PC UI | 카카오톡형 모바일 UI |
| 견적 | Estimates | EstimatesMobile |
| 클레임 | Claims | ClaimsMobile |
| 분기 기준 | `useMediaQuery` (약 600px / md) | 동일 |

### 4.3 주요 화면별 UI 패턴

| 화면 | 인터페이스 특징 |
|------|-----------------|
| 랜딩 | 마케팅형 CTA → 로그인/가입 |
| 로그인·가입 | 폼 중심 인증 |
| 대시보드 | 카드·위젯·요약 + BottomBar |

| MAP | 지도 + 마커·현장 선택 |
| 일정관리 | 월 캘린더, 현장→날짜 **드래그앤드롭**, 색상·날씨 이모지, 모달 편집 |
| 현장일정/간트 | 타임라인·간트 차트 |
| Project DSH | KPI 카드 + 기성/원가/정산/일정/리스크/AI **패널 그리드** |
| 재고 | 탭(대시보드·현황·입출고·품목·창고/현장) + 정렬 테이블 |

| 토론 | 메신저형 채팅 UI (PC/모바일 분리) |
| 정산 | 대용량 테이블·상세 폼 |

### 4.5 UI 평가 (강점 / 약점)

**강점**
- MUI로 폼·다이얼로그·반응형 뼈대 확보
- PC/모바일 **의도적 분기**(토론·견적·일정)
- 일정 DnD·날씨·상태 색상 등 실무형 시각 신호
- BottomBar로 자주 쓰는 액션 접근

**약점**
- 화면마다 톤·밀도 편차 → **디자인 시스템 문서화 부족**
- 초대형 페이지로 UI 파편화·중복 패턴
- 접근성(아이콘 라벨, 키보드) 보완 여지
- 모바일 IA가 PC와 달라 학습 비용
- DnD 라이브러리 혼용 → 터치 일관성 이슈 가능

### 4.6 UI 개선 제안

1. 공통 **디자인 토큰**(색·간격·타이포) 정리  
2. 리스트/테이블 **가상화** + 통일 필터 바  
3. 모바일 하단 내비 IA를 권한 메뉴와 맞춰 단순화  
4. DnD·제스처 라이브러리 **하나로 통일**  
5. 핵심 플로우 모바일 UX 점검 (로그인→일정→현장 저장)

## 5. 사용자 · 데이터 흐름

### 5.1 인증 · 진입

```
랜딩 → 로그인/회원가입 → Firebase Auth
                         ↓
              AuthContext + ProtectedRoute
                         ↓
              Layout(메뉴) → 권한 필터된 페이지
```

### 5.2 일반 업무 흐름 (현장 중심)

```
현장 등록/수정 (sites)
    ├─→ 사진·문서 (Storage)
    ├─→ 일정에 현장 드래그 (schedules) + 날씨 자동채움
    ├─→ 공정·기성·원가·클레임 연동
    ├─→ 견적·물량·정산
    └─→ 현장 대시보드(Project DSH)에서 KPI·리스크 요약
```

### 5.3 실시간성

- Firestore `onSnapshot`으로 목록·캘린더 **실시간 반영**
- 리스크: 구독·리렌더 과다 시 성능·비용 증가

### 5.4 보조 흐름

| 흐름 | 설명 |
|------|------|
| 일정 + 날씨 | 주소 → 좌표 → 일별 날씨 이모지 |
| 견적 + AI | 보조 API 요약(선택) |
| 엑셀 | 템플릿 업로드·내보내기 |
| PWA | 설치·캐시·오프라인 기본 |

## 7. 종합 평가

### 7.1 점수 요약

| 영역 | 등급 | 한 줄 평가 |
|------|------|------------|
| 기능 커버리지 | **A−** | 현장 운영 모듈이 넓음 |
| UX / 인터페이스 | **B** | 셸·PC/모바일 분기 있음, 화면 편차·통일 부족 |
| 아키텍처·유지보수 | **C+** | 초대형 단일 파일 다수 |
| 보안 | **C** | Auth 골격 있음, 서버 규칙·시크릿 보강 필요 |
| 성능 | **B−** | lazy 있음, 대형 페이지·구독 최적화 여지 |
| 테스트 | **D** | 자동화 테스트 거의 없음 |
| DevOps | **B** | Vite·Netlify/PWA·문서 일부 |

**종합:** 실사용 가능한 업무 밀착형 통합 앱. 기능·화면은 넓고, 구조·보안·UI 통일·테스트는 다음 단계.

### 7.2 잘된 점

1. 실무형 도메인 범위 (일정·기성·견적·재고·안전·정산)  
2. Firebase 실시간 협업  
3. 라우트 lazy / 청크 분리  
4. PWA·Drawer·BottomBar·화면별 모바일 분기  
5. DSH 패널형 현장 요약  
6. 일정 DnD, 메신저형 토론, MAP  
7. 매뉴얼·워크플로 도식

### 7.3 아쉬운 점

1. 초대형 페이지 파일  
2. UI·비즈니스 로직 혼재  
3. 인터페이스 톤 불통일  
4. 보안이 클라이언트에 치우침 (세부 값 미기재)  
5. DnD 등 의존성 중복  
6. 테스트 부재  
7. 마이그레이션 코드 번들 혼입 위험  
8. 현장명 문자열 의존  
9. 오프라인 전략 불완전 가능

## 10. 발표 시 강조 포인트

1. **무엇을** — 현장 운영을 한곳에

4. **기술** — Firebase 실시간 + PWA  
5. **한계** — 기능·화면은 넓고, 코드·보안·UI 통일·테스트는 과제
